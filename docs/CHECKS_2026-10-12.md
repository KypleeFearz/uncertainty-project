# Development checks, 12 October 2026

Development split only (n = 322, 123 clear cases). Not test evidence. Thresholds from train: clear ≤ 0.624, debatable ≥ 0.683.

## Check 1: How much of the clear-case error signal is the answer label alone?

Human majority on clear dev cases: entailment 73, contradiction 26, neutral 24.

| | GPT | Claude |
|---|---|---|
| Model answers neutral on clear dev cases | 60 / 123 | 46 / 123 |
| Majority deviations among those neutral answers | 36 / 60 | 29 / 46 |
| Majority deviations on entailment answers | 0 / 48 | 0 / 48 |
| Majority deviations on contradiction answers | 0 / 15 | 8 / 29 |
| AUROC clear cases: answer label only (train rate per label) | 0.862 [0.81, 0.91] | 0.853 [0.79, 0.91] |
| AUROC clear cases: epistemic tree | 0.948 [0.91, 0.98] | 0.869 [0.80, 0.94] |
| Difference epistemic tree minus label only (paired bootstrap) | +0.09 [0.04, 0.14] | +0.02 [−0.05, 0.09] |
| Within neutral answers: AUROC 1 − confidence / MI | 0.85 / 0.77 | 0.91 / 0.66 |
| AUROC all cases: label only vs. risk tree | 0.72 vs 0.79 | 0.68 vs 0.78 |

Reading: all GPT deviations on clear dev cases occur when GPT answers neutral. The answer label alone explains most of the clear-case signal. Within neutral answers, model confidence still separates deviations well, so the learned risk combines label and uncertainty. For GPT the tree adds significantly beyond the label; for Claude it does not.

Code change: `answer_label_only` and `epistemic_answer_label_only` in the error-risk table, `baseline_answer_label` in the dissociation table.

## Check 2: Does the clarify cue separate clarify from alternatives?

Annotated debatable cases: train 124 (56 clarify, 68 alternatives), dev 44 (19 / 25).

| AUROC clarifiable cue, clarify vs. alternatives | GPT | Claude |
|---|---|---|
| Train | 0.59 | 0.57 |
| Dev | 0.38 | 0.36 |
| Share of all cases with cue ≥ 0.5 | 17–18% | 6% |

Single cues against their own category (all annotated dev cases, n = 93): lexical 0.62 / 0.62, coreference 0.54 / 0.54, probabilistic 0.71 / 0.69.

Reading: the self-reported cues carry little information about the documented disagreement source, and none for the clarify decision. Tuning the threshold cannot fix an uninformative signal. Proposal: report clarify vs. alternatives as an exploratory, negative result; keep clarify in the demo as a design option.

Development split, same protocol (train fit, dev selection).

| Specialisation on clear errors: risk minus disagreement signal | +0.32 [0.20, 0.42] | +0.07 [−0.04, 0.18] |

Reading (development only, optimistic):
- The concern that averaging in tree leaves inflates predicted disagreement does not change disagreement detection; the distribution tree stays the primary signal, the direct tree is a robustness check.
- Answer label + confidence detects clear-case deviations as well as the full epistemic tree. Prompt-ensemble signals (MI, credal width) and cues add no measurable value for risk detection on these data.
- Relative specialisation holds in both directions for GPT; for Claude only in the disagreement direction.
- "Neutral acts as an evasive label" is a hypothesis, not a finding.

All three comparisons are now fixed as primary analyses in `config/project.json` → `analysis_plan` (sealed by the freeze).
